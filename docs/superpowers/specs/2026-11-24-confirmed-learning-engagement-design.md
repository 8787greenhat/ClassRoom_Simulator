# 確認式學習與參與情緒狀態設計

## 目的

讓學生不因教師說出正解就立刻放棄迷思；只有學生用自己的話成功表現對應概念後，才逐項更新熟練度與迷思。同時讓五位學生的注意、回答意願、挫折、尷尬與信心直接影響當輪行為，產生沉默、不知道、被點名才嘗試及答錯後防衛等可觀察差異。

## 範圍與限制

- 只支援目前的國中密度單元與合成角色，不宣稱為完整認知或情緒模型。
- 沿用 `student_states.concept_state_json`，在其中加入 `engagement`；不新增資料表或破壞舊資料。
- 更新規則保持 deterministic、可重跑；不讓生成模型自行判定自己是否學會。
- Guard 代寫與 `ResilientProvider` 的 mock fallback 不得確認學習；直接選用 Mock 的測試流程可確認，但 metadata 必須標示來源。
- 每輪每項概念最多上升一級、每項迷思最多下降一級。

## 採用方案

### 方案 A：只記錄情緒，不影響回答

最小改動，但無法驗證使用者關心的沉默、退縮與防衛，故不採用。

### 方案 B：固定規則驅動行為與兩階段確認（採用）

教師訊息先分類成待確認證據；BehaviorPlan 讀取證據與參與情緒狀態產生 `silent`、`hesitant` 或既有行為。學生回答後，再由密度單元規則檢查是否真的表達相關關係，成功才提交狀態更新。優點是可重現、可觀察、適合目前研究基線；限制是語意覆蓋有限。

### 方案 C：另用 LLM 判斷理解與情緒

語意彈性較高，但成本、波動與自評偏差都較大，不適合第一版；可在未來用人工標註資料獨立比較。

## 資料與流程

```text
教師發言
  -> deterministic 證據分類（不更新狀態）
  -> 依角色與參與情緒建立 BehaviorPlan
  -> 模型／Mock 產生學生回答
  -> 檢查來源是否可用作學習證據
  -> deterministic 學生表現分類
  -> 成功才提交概念 +1／對應迷思 -1
  -> 更新參與情緒，保存狀態與事件證據
```

`engagement` 固定保存五個 0.0–1.0 欄位：`attention`、`willingness_to_answer`、`frustration`、`embarrassment`、`confidence`。舊 row 缺少欄位時依角色預設補值；非法值限制到範圍內。

教師事件保存 staged evidence 與 `status=pending_student_response`。學生事件保存學生表現、來源資格、更新前後值、未更新原因及更新後 engagement。BehaviorPlan 保存本輪使用的 engagement 快照，讓評測觀察台的新報告可直接顯示。

## 行為規則

- 低回答意願且未被點名：`silent`，可見輸出為 `……`，仍保留一筆事件。
- 低信心、高尷尬或高挫折：`hesitant`，允許「我不知道」或簡短不確定回答。
- 被具名且問題具體：提高注意與回答意願，但不保證答對。
- 成功表現概念：信心小幅增加、挫折下降。
- 被要求解釋但未成功：挫折小幅增加、信心下降。
- 所有變動都有界且每輪幅度固定，不加入隨機數。

## 驗收

- 一般糾正、錯誤方向證據、只有教師正解、學生回答失敗，均不降低目標迷思。
- 對應證據加理解檢核，且學生成功表達關係時，才更新一級。
- Guard／fallback 回答不確認學習，直接 Mock 測試可重現完整流程。
- 五角色有不同初始 engagement；舊 DB 可讀寫並 round-trip。
- 至少有一條測試證明 `silent`、一條證明 `hesitant`、一條證明成功後情緒更新。
- API、Mock evaluation、Mock 十輪課堂與完整單元測試通過；新版本結果不得冒充真實學生證據。
