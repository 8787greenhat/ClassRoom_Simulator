# 結構化行為規劃與 Guard 重試設計

## 目的

降低固定 Guard 句型造成的模板感。學生回答仍由 Ollama 生成；程式只先決定學生當輪的理解、意圖、信心、迷思與語氣，第一次回答不合規時最多重試一次，仍失敗才套用既有 deterministic Guard。

## 範圍

- 延伸現有 `behavior.py`，不新增模型、服務或 SQLite schema。
- 每位角色先提供兩組合成示例，之後由人工覆核自然度；不把它們宣稱為真人語料。
- 保存結構化規劃、第一次與重試回答、失敗原因及最終來源，讓觀測台可區分 raw、retried、guarded 與 fallback。
- Prompt 版本升為 `density-v4.3`；evaluator 硬性規則仍為 `2.1`。

## 不做

- 不改全域預設模型；評測時可選已安裝的 7B。
- 不加入 RAG、同儕互動或新評分量尺。
- 不用已使用的 holdout v1 調整規則，也不執行本輪 Ollama 品質宣稱。

## 回答流程

`角色／狀態／教師問題 → BehaviorPlan → 兩組角色示例 → Ollama → 驗證 → 最多一次重試 → deterministic Guard → 最終回答`

`BehaviorPlan` 只描述幕後決策，不指定完整句子。重試使用原 Prompt、第一次回答及具體失敗原因；只有第二次仍失敗時才允許現有 Guard 改寫。

## 驗收

- 五個角色都有可序列化的結構化規劃與兩組示例。
- 第一次合格不重試；第一次失敗、第二次合格標成 `retried`；兩次失敗才標成 `guarded`。
- 課堂事件與評測報告保存規劃及所有生成嘗試，舊報告仍可讀。
- Mock 不呼叫重試；所有既有測試及新增定向測試通過。
