# 專案上下文

## 一句話目標

建立一套可重複測試的多學生 LLM 教學模擬器，讓師培生在國中自然科「密度」單元練習同時面對不同程度、性格及迷思的學生，並在後續以證據式評價比較 AI 與專家評分。

## 目前可運作基線

- FastAPI 提供課堂建立、查詢、教師發言與結束課堂 API。
- 單頁前端可建立課堂並顯示五位學生、狀態及逐字稿。
- Ollama `qwen2.5:3b` 是預設本地模型；不可用時回退到 deterministic mock。
- SQLite 保存 session、每位學生狀態與事件。
- 五位角色的記憶彼此隔離；迷思以 0–3 強度追蹤。
- 角色防護避免高迷思強度的學生因一次提示立即迎合教師。

## 研究焦點

1. 多位學生角色是否能保持可辨識且一致的行為？
2. 指定迷思是否會在缺乏充分教學證據時維持，而非迎合使用者？
3. 未來 AI 教學評價能否與專家評分達到可接受的一致性？

## Proposal 對齊基準

原始 proposal「基於多代理人大型語言模型之互動式教學模擬與教師教學評價系統」定義的核心承諾如下：

- 系統在單一電腦與瀏覽器中執行，讓師培生以文字或麥克風進行模擬試教。
- 同一個大型語言模型扮演五位學生，但每位學生必須有不同角色提示、獨立記憶與角色狀態；角色涵蓋主動、一般、指定迷思、害羞被動與容易分心。
- 課堂管理負責選擇發言者、控制節奏與事件，避免所有學生同時回答或對話無限制偏離主題。
- 系統保存發言者、逐字稿、時間與課堂事件；課後才由評價流程讀取完整紀錄。
- 教學評價採「程式計算加固定規準評分」：反應時間與參與分布由程式計算；提問品質、對話品質與迷思處理由模型依量尺分析，而且每項判斷都必須引用發言證據。資料不足時必須明示，不得補寫事件。
- 評價可信度不能由學生 Agent 的滿意度自行證明。同一逐字稿應重複評分三次檢查穩定性，並由具教學背景者使用同一量尺評分，再比較 AI 與人工結果。
- 預定使用約 5–10 名師培生進行易用性與實用性試用；涉及真人資料前，需先完成倫理、同意、去識別化與保存規則。
- 系統只定位為師培生練習與自我反思工具，不代表真實學生，也不取代正式教師評鑑。

教授與學長姐意見形成的後續收斂決策：第一階段不支援任意主題，先完整驗證國中自然科「密度」；學生需保有一定程度的迷思頑固性；評分必須與專家結果做統計比較。RAG 是用來落實教材範圍約束的後續方法，目前尚未實作。

未來 RAG 語料應至少區分三類權限與用途：學生可接觸的教材內容、教師端教案與解答、用於模擬錯誤反應的迷思或學生作答案例。不可把三類資料直接混入同一個學生檢索上下文。

## 現階段不做

- 不宣稱支援任何課程主題。
- 不把 Prompt-only 的內建密度知識描述成完整 RAG。
- 不在沒有專家資料時宣稱 AI 評分可信。
- 不蒐集真實學生個資或錄音。

## 主要指令

```powershell
.\run.ps1
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m classroom_simulator.evaluation --provider mock
.\.venv\Scripts\python.exe -m classroom_simulator.classroom_scenario --provider mock
```

## 環境設定

- `CLASSROOM_DB_PATH`：SQLite 檔案位置；預設 `data/classroom.db`。
- `OLLAMA_BASE_URL`：預設 `http://localhost:11434`。
- `OLLAMA_MODEL`：預設 `qwen2.5:3b`。

## 完成定義

一個開發批次只有在程式、測試、相關文件與開發紀錄同步更新，且所有必要驗證通過後才算完成。
