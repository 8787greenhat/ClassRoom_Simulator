## 自動檢查標準

每輪檢查：點名角色正確、行為類型正確、回答 1–45 字、不是 placeholder、沒有多行、沒有透露 AI 身分；指定輪次額外檢查迷思強度。全堂檢查：20 筆事件、五位角色都發言、課堂正常結束、迷思強度逐步降到 1。

## Run 1 發現與修正

Run 1 的自動硬性檢查原先顯示 10/10，但人工檢查發現第 3、8 輪只有「學生發言」，是模型照抄 JSON schema 範例；第 6 輪另有多行回答。這表示舊檢查存在假陽性。

對應修正：

- Prompt 改為 `density-v4.1`，明確禁止輸出「學生發言／學生回答」。
- Provider 把 placeholder 視為失敗，正式系統改走 mock fallback。
- 多行輸出正規化成單一課堂發言。
- 完整課堂硬性檢查加入 `not_placeholder` 與 `single_line`。

## 成果判定

### 已達成

- 完整課堂可從建立、10 輪互動、狀態保存到結束，不會因單次模型失敗中斷。
- 點名與五角色狀態隔離正確。
- 迷思不是一次消失，而是依教學證據從 3 降到 2、1。
- 分心學生可被具體問題拉回課程。
- placeholder、空回應、provider fallback 與 guard 都可追蹤。

### 部分達成

- 角色語氣有差異，但主動、一般與迷思角色仍不夠穩定。
- 內容多數與密度有關，但自動硬性通過不等於回答完整或像真實學生。
- 系統可維持課堂，但本次只有 70% 回答是原生 Ollama，模型可靠性不足。

### 尚未達成

- 學生彼此附和、反駁、插話或受同學影響。
- 經專家或師培生評定的學生真實度。
- AI 評分與專家評分的統計一致性。
- 不依賴人工規則或固定 fallback 的穩定角色表現。

## 優先修正

1. 將「謝謝老師／謝謝提醒」納入高迷思強度的迎合檢查，並處理超過 45 字的回答。
2. 新增回答是否真正回應教師要求的人工標註與 holdout 情境。
3. 分開報告 raw Ollama、guarded、fallback 三種成績。
4. 完成個別角色真實度驗證後，再加入學生之間互動。

## 結論

目前已是可完整操作且不易中斷的 MVP 課堂流程，但還不能稱為高真實度課堂模擬。系統流程與狀態控制表現穩定；主要風險已從「程式能否跑完」轉為「回答是否真的像該角色、是否直接回應問題，以及模型原生可靠性」。
