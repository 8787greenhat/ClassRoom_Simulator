# 決策紀錄

## ADR-001：先聚焦國中自然科「密度」

- 日期：2026-10-22
- 狀態：已採用
- 決定：第一階段只完整支援密度單元，不開放任意科目承諾。
- 理由：角色迷思、教材邊界與測試答案才能明確，符合教授建議的小範圍精準驗證。

## ADR-002：Prompt baseline 先於 RAG

- 日期：2026-10-22
- 狀態：已採用
- 決定：先建立 Prompt、角色狀態與可重複評測，再加入 RAG。
- 理由：可先分離角色模擬問題與檢索問題，控制開發量並形成比較基線。

## ADR-003：本地 Ollama 搭配 deterministic fallback

- 日期：2026-10-22
- 狀態：已採用
- 決定：開發預設模型為 Ollama `qwen2.5:3b`；服務不可用時用 mock，測試不依賴模型或網路。
- 代價：mock 只能驗證流程與規則，不能代表模型品質。

## ADR-004：迷思是有強度的 session 狀態

- 日期：2026-10-22
- 狀態：已採用
- 決定：迷思強度為 0–3；有概念證據加理解檢核時，每輪最多下降一級。
- 理由：避免 LLM 投人所好，也讓變化可記錄及測試。

## ADR-005：研究主張必須來自重複評測

- 日期：2026-10-22
- 狀態：已採用
- 決定：單次示範只用於除錯；角色品質與 AI 評分可信度必須用版本化情境、多次執行與統計摘要佐證。
- 理由：模型輸出具有隨機性，個別成功案例不能支持研究結論。

## ADR-006：先加入受控分心行為，不擴大年齡範圍

- 日期：2026-10-22
- 狀態：已採用（經使用者確認）
- 決定：維持國中自然科密度範圍，在既有分心角色加入 `distracted`、`off_topic`、`imaginative`、`redirected` 等可觀察行為；暫不宣稱完整模擬小學生。
- 理由：增加真實課堂干擾，同時避免把年齡、語言程度及課程單元三種變因混在一起。
- 限制：行為必須受情境控制，不能每輪隨機講廢話；模型原生成功與 guard 修正後成功必須分開記錄。

## ADR-007：先提供逐輪模型比較，不立即更換全域預設

- 日期：2026-11-10
- 狀態：已採用
- 決定：網頁只列出本機 Ollama 已安裝模型，允許每輪切換並在事件 metadata 保存模型名稱；全域預設暫時維持 `qwen2.5:3b`。
- 理由：固定 baseline 50 次比較中，`qwen2.5:7b` 為 76%，高於 3B 的 58%，但平均延遲 5.16 秒，約為 3B 的 2.00 倍。先讓使用者依品質／速度情境選擇，再以人工量尺及新 holdout 決定是否正式更換研究主模型。
- 限制：上述通過率是 evaluator 2.1 的角色 marker、長度與禁詞硬性檢查，不是學生真實度；目前結果不可單獨支持研究結論。

## ADR-008：評測工作使用本機單一 worker 與不可變封存 overlay

- 日期：2026-11-23
- 狀態：已採用（經使用者確認）
- 決定：第一版評測觀察台使用程序內單一背景 worker，將工作與新報告原子寫入 `data/evaluations/`；四份既有研究報告保持唯讀，人工覆核另存 overlay 並以來源 hash 綁定。
- 理由：目前部署是單機 FastAPI 與本機 Ollama。JSON 可保留完整評測證據且不污染課堂 session／事件 schema；單一 worker 可避免多個評測同時爭用本機模型。
- 代價：程序重啟後未完成工作只能標示 `interrupted`，不能自動續跑；多程序或多主機部署也無法共用這個 in-process 排程。
- 升級門檻：若需要取消／重試、跨程序執行、多使用者排程、長時間可靠工作或遠端 worker，再評估持久化 queue；在此之前不提前加入額外服務。
- 資料限制：`data/evaluations/` 只保存本機工作與覆核，不進 Git；需要成為研究證據的選定報告須人工整理至 `docs/evaluations/`，並保留版本與來源資訊。

## ADR-009：行為規劃與語句生成分離，Guard 前最多重試一次

- 日期：2026-11-23
- 狀態：已採用（經使用者確認）
- 決定：density-v4.3 先建立可序列化的 `BehaviorPlan`，描述學生當輪理解、意圖、信心、迷思與語氣，再以每角色兩組合成示例引導 Ollama 生成。第一次回答不合規時附失敗原因重試一次；第二次仍失敗才使用既有 deterministic Guard。
- 理由：原流程由 Guard 直接替換固定句子，雖能通過硬性規則但容易模板化。結構化規劃控制「為什麼這樣回答」，不直接指定完整句子；單次重試保留模型語言變化，同時限制延遲與無限重試。
- 證據：新事件與評測報告分開保存 `behavior_plan`、`generation_attempts`、`retry_count`，來源分類新增 `retried`；不得把 retried 或 guarded 算成模型第一次原生成功。
- 限制：目前兩組示例是合成開發資料，不是真人學生語料；7B 五案例單次 smoke 只能證明流程可執行，不能證明真實感改善。holdout v1 已使用，不得拿來調整 density-v4.3。
