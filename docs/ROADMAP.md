# 開發路線圖

## 下一次開發目標

已保留 density-v4.2 與 holdout v1 歷史基線，完成 density-v4.3 的結構化行為規劃／單次重試、density-v4.4 的概念狀態、density-v4.5 的學生表現確認與參與／情緒狀態，以及 density-v4.6 的教師動作對齊。下一個批次仍先驗證角色原生可靠度，不直接跳到完整 RAG：

1. 先用評測觀察台完成 holdout v1 與重要 baseline 的逐筆人工標註，分開保留硬性規則與人工判讀。
2. 使用 baseline 與人工開發案例改善主動、迷思及害羞角色，不拿 holdout v1 反覆調參。
3. 完成人工開發案例調整後建立全新的 holdout v2，分開報告 raw Ollama、retried、guarded、fallback 與人工判讀。
4. 只有新 holdout 顯示角色可靠度足夠，才進入 RAG pilot。

### 角色真實度優化順序（v4.7 之後）

1. **先建立開發矩陣，不再靠單張截圖調 Prompt**：以五角色 × 定義／比較／解釋／應用／迷思檢核／回想六種教師動作建立人工開發案例；每筆標註是否直接回答、角色一致、像國中生，以及簡繁混用、過度熟練、照抄示例等失敗原因。這批案例可反覆開發，但不可當 holdout。
2. **先限制知識上限與示例複製**：讓當輪可說出的概念受 `concept_mastery` 約束；低熟練或分心角色即使答對，也只能說出不完整理解。記錄回答與合成示例的近似度，避免 3B 逐字搬用 few-shot。先用 deterministic 規則與 Prompt A/B，不新增第二個 LLM judge。
3. **再做單模型 context-first A/B**：比較現行一次生成，與「先產生不帶角色口吻的內容骨架，再依角色／情緒改寫」兩種流程；分開量測直接回答率、角色真實度、語句多樣性、raw／retried／guarded 比例與延遲。只有人工判讀有明顯收益才接受多一次模型呼叫。
4. **有足夠人工偏好資料才評估微調**：若 7B、Prompt 與 context-first 仍無法穩定改善，再評估本機 LoRA／DPO。合成回答不能直接當成真人學生資料；開始前須另外確認資料來源、授權與研究用途。
5. **最後建立 holdout v2**：使用未出現在 Prompt、開發矩陣與人工討論中的新題目，盲評後分開報告硬性規則、人工三指標、來源分類及延遲；通過後才進入 RAG pilot。

短期驗收重點不是「答案越正確越好」，而是回答教師當輪問題、符合角色目前能懂的程度，並保留自然的不確定、沉默或錯誤。v4.6 的單案例 5 次 smoke 只驗證題型錯置已受控，不作為上述階段的完成證據。

模型比較工具已完成：介面可逐輪選擇本機模型，CLI 可用 `--model`，評測保存延遲與單輪錯誤。2026-11-10 baseline 比較顯示 7B 的硬性規則通過率優於 3B，但尚未完成人工真實度標註，因此不改變上述下一步順序。

接續的 RAG pilot 只限密度單元。開始前需要使用者提供或選定具授權且版本固定的教材；第一版語料可包含教材、教案、作業與迷思案例，但必須分開索引與控制學生／教師可見範圍。驗收採 Prompt-only 與 RAG 對照，檢查正確性、教材越界率、角色真實度、檢索證據與延遲。
