# 開發路線圖

## Phase 0 — 可重現基線（目前）

- [x] 五位學生角色與獨立狀態
- [x] FastAPI、SQLite、網頁操作流程
- [x] Ollama + mock fallback
- [x] 迷思強度與防迎合 guard
- [x] 自動測試
- [x] 專案上下文、架構、決策與開發紀錄
- [x] 第一版角色一致性評測工具

## Phase 1 — Prompt/角色實驗

- [ ] 為五位角色定義可觀察的評測指標與失敗例
- [ ] 每個固定情境重複執行至少 10 次 Ollama 評測
- [ ] 保存模型、參數、Prompt 版本與聚合結果
- [ ] 比較不同 Prompt 的角色一致性與迎合率

完成條件：有版本化情境、可重跑命令、原始結果及摘要，不以主觀挑選範例判斷。

## Phase 2 — 受控教材/RAG

- [ ] 由使用者確認教材來源、授權與版本
- [ ] 建立密度單元小型語料與切片策略
- [ ] 回應紀錄檢索片段與引用來源
- [ ] 比較 Prompt-only 與 RAG 的正確性、越界率及延遲

## Phase 3 — 班級互動

- [ ] 定義何時允許學生回應同儕
- [ ] 控制每輪發言數，避免無限代理人對話
- [ ] 測試參與公平性、角色記憶污染與延遲

## Phase 4 — 教學評價

- [ ] 與指導老師確認評分量尺及專家評分流程
- [ ] 評分必須引用逐字稿證據
- [ ] 建立去識別化資料匯出
- [ ] 依資料尺度評估 Pearson/Spearman、MAE 與評分者一致性（ICC 或加權 kappa）

## Phase 5 — 使用者研究與擴充

- [ ] 先處理倫理、同意、隱私與保存期限
- [ ] 小規模可用性測試
- [ ] 達成密度單元驗證後，再決定下一單元或科目

## 待使用者決定（到該階段前不阻擋目前開發）

1. RAG 要採用哪一份具授權的教材或自編講義。
2. 教學評價量尺由誰制定，以及專家樣本數與雙評分流程。
3. 是否收集真人錄音/逐字稿；若是，須先定義倫理與資料治理。
4. 下一個擴充單元，不在密度驗證完成前加入。
