# 開發路線圖

## 下一次開發目標

下一個批次先完成「角色回答可靠度與未見案例驗證」，不直接跳到完整 RAG：

1. 修正迷思角色過早迎合、超過 45 字及未直接回答教師要求的情況。
2. 為「是否真正回答問題」加入可人工覆核的標註欄位，不以關鍵字命中取代語意判斷。
3. 建立全新的 holdout 課堂與角色案例，分開報告 raw Ollama、guarded、fallback 與人工判讀結果。
4. 以固定版本結果決定是否進入 RAG pilot；不可用同一批已看過的情境反覆調整並宣稱改善。

接續的 RAG pilot 只限密度單元。開始前需要使用者提供或選定具授權且版本固定的教材；第一版語料可包含教材、教案、作業與迷思案例，但必須分開索引與控制學生／教師可見範圍。驗收採 Prompt-only 與 RAG 對照，檢查正確性、教材越界率、角色真實度、檢索證據與延遲。

- [ ] 與指導老師確認評分量尺及專家評分流程

## Phase 5 — 使用者研究與擴充

- [ ] 先處理倫理、同意、隱私與保存期限
- [ ] 小規模可用性測試
- [ ] 達成密度單元驗證後，再決定下一單元或科目

## 待使用者決定（到該階段前不阻擋目前開發）

1. RAG 要採用哪一份具授權的教材或自編講義。
2. 教學評價量尺由誰制定，以及專家樣本數與雙評分流程。
3. 是否收集真人錄音/逐字稿；若是，須先定義倫理與資料治理。
4. 下一個擴充單元，不在密度驗證完成前加入。
